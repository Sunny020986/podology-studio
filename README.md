# Подологічний кабінет: онлайн-запис і чат

Сайт для запису клієнтів, вибору вільного часу і чату з оператором. Один майстер, без онлайн-оплати.

## Що всередині

- **Сайт** (`/`): список послуг, вибір дати і вільного часу, форма запису, чат з оператором.
- **Адмінка** (`/admin`): список клієнтів з історією візитів і нотатками майстра, записи на день зі зміною статусу, чат з клієнтами, робочі години, блокування часу, послуги і ціни.
- **Сервер**: Node.js + Express, живий чат через WebSocket, база SQLite в одному файлі.

## Вимоги

- Node.js 20 або новіший (перевірити: `node -v`).
- Для Windows, якщо встановлення `better-sqlite3` видає помилку збірки: встановіть Node LTS з прапорцем «Tools for Native Modules» або Visual Studio Build Tools.

## Запуск на локальній машині

```bash
cd podology-studio
npm install
ADMIN_TOKEN=придумайте-довгий-токен npm start
```

Windows (PowerShell):

```powershell
cd podology-studio
npm install
$env:ADMIN_TOKEN="придумайте-довгий-токен"; npm start
```

Потім відкрийте:

- сайт: http://localhost:3000
- адмінка: http://localhost:3000/admin (введіть той самий токен)

Якщо `ADMIN_TOKEN` не задати, сервер створить випадковий токен і збереже його у `data/admin-token.txt`.

## Налаштування

1. **Сповіщення в Telegram** про новий запис і нове питання в чаті: адмінка, вкладка «Кабінет», там покрокова інструкція. Серверу потрібен доступ до `api.telegram.org`.
2. **Дані кабінету** (назва, підзаголовок, адреса, телефон): адмінка, вкладка «Кабінет». Зберігаються в базі. `public/config.js` містить лише запасні значення на випадок, якщо сервер не відповів.
3. **Послуги і ціни**: вкладка «Послуги» в адмінці. Стартові послуги і описи в `src/db.js` є лише прикладом. Ціна `0` показується як «ціна уточнюється».
4. **Розклад**: вкладка «Розклад». Крок пропозиції часу 30 хвилин, запис не раніше ніж за 60 хвилин від зараз.
5. **Перерви і вихідні**: щотижневі перерви (обід) додаються у вкладці «Розклад», розділ «Перерви»; разові проміжки на конкретну дату у вкладці «Блокування»; вихідний день позначається в розкладі.
6. **Тема**: сайт і адмінка мають світлу й темну тему. За замовчуванням тема повторює налаштування системи відвідувача, кнопка в шапці перемикає її вручну. Кольори обох тем задаються змінними на початку й у кінці `public/styles.css`.

## Захисні обмеження

| Що обмежено | Значення | Як змінити |
|---|---|---|
| Запис уперед | 90 днів від сьогодні | змінна `BOOKING_HORIZON_DAYS` |
| Записів з однієї IP-адреси | 10 за годину | змінна `BOOKINGS_PER_HOUR` |
| Активних записів на один телефон | 3 | константа `MAX_ACTIVE_PER_PHONE` у `src/server.js` |
| Невдалих входів в адмінку з однієї IP-адреси | 10 за 15 хвилин, далі блокування до кінця цих 15 хвилин | константи `LOGIN_MAX_FAILS`, `LOGIN_WINDOW_MS` |

Якщо оператор сам записує клієнтів через сайт з комп'ютера кабінету і впирається в ліміт 10 записів за годину, збільште `BOOKINGS_PER_HOUR`.

Якщо сайт стоїть за оберненим проксі (Caddy, Nginx), задайте `TRUST_PROXY=1`. Без цього сервер бачить усіх відвідувачів під адресою проксі, і ліміти стануть спільними на всіх.

Лічильники зберігаються в пам'яті й обнуляються після перезапуску сервера.

## Де зберігаються дані

Усе в `data/studio.db` (SQLite).

### Резервні копії

`node scripts/backup.js` робить цілісну копію бази просто під час роботи сайту, зупиняти сервер не треба. Копії лягають у `backups/` (або `BACKUP_DIR`), старші за 30 днів (`BACKUP_KEEP_DAYS`) видаляються. Якщо задано `BACKUP_REMOTE=користувач@адреса:/шлях/`, свіжа копія ще й копіюється на іншу машину через `scp` (потрібен SSH-ключ без пароля).

Щоденний запуск о 03:15 через systemd:

```bash
cp deploy/podology-backup.service deploy/podology-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now podology-backup.timer
systemctl start podology-backup.service   # перший запуск одразу
journalctl -u podology-backup -n 20       # результат
```

Відновлення: зупиніть сайт (`systemctl stop podology`), замініть `data/studio.db` потрібною копією, видаліть поруч файли `studio.db-wal` і `studio.db-shm`, якщо вони є, і запустіть сайт знову.

Часовий пояс береться з комп'ютера, де запущено сервер. Для Києва це має бути `Europe/Kyiv`.

## Обмеження поточної версії

- Нагадування клієнтам (SMS, email, Telegram) не реалізовані. Майстру сповіщення в Telegram приходять.
- Немає авторизації клієнтів: записатися може будь-хто, хто має доступ до сайту.
- Токен адміна один на всіх. Для кількох адміністраторів потрібна окрема система облікових записів.
- Для доступу з інтернету потрібні HTTPS і обернений проксі (наприклад, Caddy або Nginx). Без них токен і чат передаються відкрито.
