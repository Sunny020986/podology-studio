# Подологічний кабінет: онлайн-запис і чат

Сайт для запису клієнтів, вибору вільного часу і чату з оператором. Один майстер, без онлайн-оплати.

## Що всередині

- **Сайт** (`/`): список послуг, вибір дати і вільного часу, форма запису, чат з оператором.
- **Адмінка** (`/admin`): записи на день зі зміною статусу, чат з клієнтами, робочі години, блокування часу, послуги і ціни.
- **Сервер**: Node.js + Express, живий чат через WebSocket, база SQLite в одному файлі.

## Вимоги

- Node.js 20 або новіший (перевірити: `node -v`).
- Для Windows, якщо встановлення `better-sqlite3` видає помилку збірки: встановіть Node LTS з прапорцем «Tools for Native Modules» або Visual Studio Build Tools.

## Запуск на локальній машині

```bash
cd podology-studio
npm install
ADMIN_TOKEN=придумайте-довгий-токен npm start
```

Windows (PowerShell):

```powershell
cd podology-studio
npm install
$env:ADMIN_TOKEN="придумайте-довгий-токен"; npm start
```

Потім відкрийте:

- сайт: http://localhost:3000
- адмінка: http://localhost:3000/admin (введіть той самий токен)

Якщо `ADMIN_TOKEN` не задати, сервер створить випадковий токен і збереже його у `data/admin-token.txt`.

## Налаштування

1. **Дані кабінету**: `public/config.js` (назва, адреса, телефон). Значення в квадратних дужках замініть своїми.
2. **Послуги і ціни**: вкладка «Послуги» в адмінці. Стартові послуги і описи в `src/db.js` є лише прикладом. Ціна `0` показується як «ціна уточнюється».
3. **Розклад**: вкладка «Розклад». Крок пропозиції часу 30 хвилин, запис не раніше ніж за 60 хвилин від зараз.
4. **Перерви і вихідні**: вкладка «Блокування» для окремих проміжків, або вихідний день у розкладі.

## Де зберігаються дані

Усе в `data/studio.db` (SQLite). Щоб зробити резервну копію, зупиніть сервер і скопіюйте цей файл.

Часовий пояс береться з комп'ютера, де запущено сервер. Для Києва це має бути `Europe/Kyiv`.

## Обмеження поточної версії

- Нагадування клієнтам (SMS, email, Telegram) не реалізовані.
- Немає авторизації клієнтів: записатися може будь-хто, хто має доступ до сайту.
- Токен адміна один на всіх. Для кількох адміністраторів потрібна окрема система облікових записів.
- Для доступу з інтернету потрібні HTTPS і обернений проксі (наприклад, Caddy або Nginx). Без них токен і чат передаються відкрито.
