# Подологічний кабінет: онлайн-запис

Сайт для запису клієнтів до подолога з адмінкою для власника й майстрів. Мова інтерфейсу, коментарів у коді й комітів — українська.

## Стек
- Node.js 20+, Express 4, SQLite (`better-sqlite3`), WebSocket (`ws`) для чату. Інших залежностей немає, фреймворків на фронтенді немає: звичайний JS у `public/`.
- База — один файл `data/studio.db` (шлях задає `DB_PATH`). Фото майстрів — `data/uploads/masters/`.
- Міграції не окремими файлами: кожен модуль при старті сам додає таблиці й колонки (`CREATE TABLE IF NOT EXISTS`, `PRAGMA table_info` + `ALTER TABLE`). Нова колонка = перевірка в тому ж стилі, без видалення даних.

## Структура
- `src/server.js` — Express: публічне API, вхід адміна й майстрів, ролі, більшість адмін-маршрутів, чат, нагадування.
- `src/db.js` — схема, стартові дані, порядок міграцій (`createMasterTables` — останньою, після стартових даних).
- `src/slots.js` — вільний час: `masterFreeSlots` (один майстер), `freeSlots` (майстер або «будь-хто»), `pickMaster`.
- `src/masters.js` — майстри: таблиці, міграція першого майстра, вкладка «Майстри» (додати, заблокувати, приховати, фото).
- `src/admin-appointments.js` — ручний запис, перенесення, слоти для адміна, дані календаря.
- `src/accounts.js` — кабінет клієнта (телефон + пароль, Telegram, скасування й перенесення).
- `src/reviews.js`, `src/repeat.js`, `src/waitlist.js`, `src/stats.js`, `src/tips.js`, `src/seo.js` — відгуки, повторний візит, черга очікування, статистика, поради, SEO.
- `src/telegram.js` — бот: сповіщення в чат кабінету, клієнтам і майстрам; посилання `t.me/<бот>?start=<код>`.
- `public/` — `index.html`+`app.js` (сайт), `account.js` (кабінет), `effects.js` (ефекти, вимикаються при «зменшити рух»), `admin.html`+`admin.js` (адмінка), `review.html` (форма відгуку), `styles.css` (усі стилі, кольори через CSS-змінні; лише світла тема).
- `scripts/backup.js` + `deploy/podology-backup.*` — щоденна резервна копія бази й фото.
- `src/client-photos.js` — фото стану стоп клієнта (історія лікування). Файли в `data/private/client-photos/`, не в `public`; віддаються лише через `/api/admin/client-photos/:id/file` з перевіркою доступу.
- `src/privacy.js` — сторінка `/privacy` (які дані збирає сайт і навіщо). Будується з налаштувань кабінету, ПІБ ФОП — поле `owner_legal`.
- `src/security.js` — заголовки безпеки (CSP та інші) і `GET /healthz`. Новий зовнішній ресурс (шрифт, карта, скрипт) треба дозволити в CSP, інакше браузер його заблокує.
- `scripts/healthcheck.js` + `deploy/podology-health.*` — сторож: кожні 2 хв перевіряє `/healthz`, пише в Telegram, коли сайт ліг і піднявся.

## Ролі й доступ
- Суперадмін — Bearer-токен `ADMIN_TOKEN`. Майстер — логін і пароль, сесія в `master_sessions`.
- `app.use('/api/admin', requireAdmin)` ставить `req.role` (`super` або `master`) і `req.masterId`.
- Майстрові дозволені лише маршрути зі списку `MASTER_ROUTES` у `server.js`; решта — 403. Новий маршрут для майстра треба додати в цей список і обмежити дані через `scopeMaster(req)` / `ownsAppt(req, id)`.
- **Важливо:** в Express перевірка доступу діє лише на маршрути, зареєстровані ПІСЛЯ `app.use('/api/admin', requireAdmin)`. Адмін-маршрут вище цього рядка буде відкритий усім (така помилка вже була й виправлена).
- Після змін у правах перевіряти: без токена — 401, майстер на чуже — 403.

## Запуск локально
```bash
npm install
ADMIN_TOKEN=довгий-токен PORT=3000 DB_PATH=./data/studio.db npm start
```
Сайт: `/`, адмінка: `/admin`. Без `ADMIN_TOKEN` сервер створює випадковий і пише його в `data/admin-token.txt`.

Змінні середовища: `ADMIN_TOKEN`, `PORT`, `DB_PATH`, `BOOKING_HORIZON_DAYS` (90), `BOOKINGS_PER_HOUR` (10), `TRUST_PROXY` (1 за Caddy/Nginx), `TELEGRAM_API`, `BACKUP_DIR`, `BACKUP_KEEP_DAYS`, `BACKUP_REMOTE`.

## Розгортання (Proxmox)
- Контейнер «Podology-studio» (Proxmox, контейнер 105), код у `/opt/podology-studio/app`, власник файлів — користувач `podology`, служба systemd — `podology`.
- Оновлення (від root у контейнері):
  ```bash
  su -s /bin/bash podology -c "cd /opt/podology-studio/app && node scripts/backup.js && git pull && npm install"
  systemctl restart podology
  ```
  `git pull` від root дає «dubious ownership» — тому команди через `su ... podology`.
- Сайт зараз доступний у локальній мережі за адресою `http://192.168.3.70:3000`. Для посилань у Telegram в адмінці («Кабінет» → «Адреса сайту») має бути публічна адреса.

## Робота з репозиторієм
- Гілка за замовчуванням `main`; зміни робляться в окремій гілці й зливаються в `main` після перевірки (зазвичай перемоткою).
- Після push у гілку з неповним клоном оновлювати `origin/<гілка>` явно: `git fetch origin +refs/heads/<гілка>:refs/remotes/origin/<гілка>`.

## Правила
- Не вигадувати ціни, факти про майстрів, відгуки, статистику: лише дані від власника. Поради з догляду додаються чернетками (неопублікованими).
- Нові адмін-функції — з урахуванням ролей (суперадмін бачить усіх і обирає майстра, майстер — лише своє).
- Ефекти на сайті — лише в `effects.js` і під класом `.fx` (його немає при «зменшити рух»).
- Час у базі для `created_at`/`updated_at` — UTC (`datetime('now')`); дати й час записів — місцеві (Київ).
- Перед злиттям: `node --check` для змінених файлів і перевірка на тестовій копії бази (копіювати разом із `-wal`/`-shm`).
- Фото стану стоп — медичні дані клієнта. Доступ: суперадмін — усі, майстер — лише клієнтів, яких веде (`canSeeClient`). Ніколи не класти їх у `public/` і не давати прямого посилання. Видаляє суперадмін або майстер, який додав фото. Нове фото приймається лише після позначки згоди клієнта (таблиця `client_photo_consent`, хто й коли позначив або відкликав).
- Нове поле чи форма з даними клієнта — допиши їх на сторінку `/privacy` (`src/privacy.js`), щоб перелік відповідав дійсності.
- Тексти для клієнтів і майстрів — прості, без жаргону, з точними числами замість «кілька».
